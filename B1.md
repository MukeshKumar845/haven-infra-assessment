# B1 — The Glacier cost gotcha

What's the actual cost impact of an early deletion after archival? How would you redesign the
lifecycle so this stops quietly costing more than budgeted?

In this configuration, `GLACIER` is S3 Glacier Flexible Retrieval, which has a 90-day minimum
storage duration. If an object is deleted after 10 days in Glacier, AWS still charges for the
remaining 80 days of that minimum period, prorated by the object's size. That is 10 days of
actual Glacier storage plus an early-deletion charge equivalent to 80 more days. The deletion
can still happen immediately to meet the seller's 30-day deletion SLA; the fee does not mean the
object must be retained. The dollar amount depends on object size and AWS region. Glacier also
bills per-object metadata overhead (40 KB per object). [AWS documents the 90-day minimum and
metadata overhead](https://docs.aws.amazon.com/AmazonS3/latest/userguide/glacier-storage-classes.html)
and the [prorated early-deletion charge](https://docs.aws.amazon.com/AmazonS3/latest/userguide/troubleshoot-lifecycle.html).

Keep photos in S3 Standard, which has no minimum-duration early-deletion fee, while they remain
eligible for seller deletion, and transition them to Glacier only after the deletion-request
eligibility window has closed. Tag deletion requests and process them promptly; do not delay
required deletion just to avoid the fee. If sellers can request deletion at any time, no Glacier
transition date can guarantee zero early-deletion charges, so either keep those objects in an
immediate-deletion-friendly class or explicitly budget and monitor the fee. Add cost reporting
and alerts for early-deletion charges so the tradeoff is visible.
